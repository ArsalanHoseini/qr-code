# مدیریت QR

سامانه مستقل و فارسی مدیریت کدهای QR ثابت و پویا با PHP و MySQL. رابط کاربری راست‌به‌چپ است و بدون WordPress یا فریم‌ورک سنگین اجرا می‌شود.

## امکانات

- راه‌اندازی امن نخستین مدیر، ورود/خروج مبتنی بر Session و محدودسازی تلاش ورود
- کد ثابت برای URL، متن و ایمیل با رنگ‌بندی و خروجی PNG/SVG
- کد پویا با شناسه تصادفی و غیرقابل‌حدس، مقصد قابل‌ویرایش و امکان فعال/غیرفعال‌سازی
- داشبورد، جست‌وجو، فیلتر، صفحه‌بندی، ویرایش و بایگانی نرم
- ثبت آمار اسکن بدون ذخیره IP خام: زمان، ارجاع‌دهنده، دسته دستگاه، مرورگر و سیستم‌عامل
- محافظت CSRF، Queryهای آماده PDO، escape خروجی، اعتبارسنجی scheme URL و تنظیم امن Cookie
- طراح حرفه‌ای QR با preset، شکل نقاط و گوشه‌ها، گرادیان، لوگو، قاب، تصحیح خطا و شاخص ایمنی اسکن

## نیازمندی‌ها

- PHP 8.2 یا جدیدتر با `pdo_mysql`، `gd`, `mbstring`, `openssl` و `zip`
- MySQL 8 یا MariaDB سازگار
- Composer 2
- Document root وب‌سرور باید دقیقاً پوشه `public/` باشد.

## اجرای محلی با Laragon

محیط این پروژه با PHP 8.4.25، MySQL 8.0.30 و Composer 2.8.9 آزمایش شده است.

1. Laragon و سرویس MySQL را روشن کنید.
2. در PowerShell و پوشه پروژه، وابستگی‌ها را نصب کنید. اگر ZIP در PHP CLI غیرفعال است، فقط برای همین فرمان آن را فعال کنید:

```powershell
php -d extension=zip C:\ProgramData\ComposerSetup\bin\composer.phar install
```

3. فایل تنظیمات را بسازید (در نسخه تحویلی، `.env` محلی از قبل آماده است):

```powershell
Copy-Item .env.example .env
```

4. دیتابیس و جدول‌ها را وارد کنید:

```powershell
Get-Content -Raw database\schema.sql | C:\laragon\bin\mysql\mysql-8.0.30-winx64\bin\mysql.exe -h 127.0.0.1 -u root
```

اگر مسیر نسخه MySQL متفاوت است، بخش نسخه را با پوشه موجود در `C:\laragon\bin\mysql` جایگزین کنید. اگر root رمز دارد، `-p` را اضافه و `DB_PASSWORD` را در `.env` تنظیم کنید.

5. وب‌سرور توسعه را اجرا کنید:

```powershell
php -S 127.0.0.1:8000 router.php
```

سپس [http://127.0.0.1:8000/setup](http://127.0.0.1:8000/setup) را باز کنید و نخستین مدیر را بسازید. وب‌سرور داخلی PHP فقط برای توسعه است.

## آزمون‌ها

```powershell
php vendor\bin\phpunit
```

آزمون‌های خودکار خروجی PNG/SVG، رد schemeهای ناامن و تشخیص سطح بالای دستگاه را پوشش می‌دهند. چک‌لیست آزمون دستی در `tests/MANUAL_CHECKLIST.md` قرار دارد.

## ساختار پروژه

```text
app/                 منطق برنامه، امنیت، دیتابیس، QR و Viewها
database/schema.sql  ساخت دیتابیس و جداول
public/              تنها Document root عمومی، Front Controller و Assetها
tests/               آزمون خودکار و چک‌لیست دستی
vendor/              وابستگی‌های Composer (در Git ثبت نمی‌شود)
.env                 تنظیمات محرمانه محلی (در Git ثبت نمی‌شود)
.env.example         نمونه تنظیمات بدون رمز
router.php           Router مخصوص وب‌سرور توسعه PHP
```

## استقرار روی هاست اشتراکی

1. یک دیتابیس و کاربر MySQL با رمز قوی و دسترسی فقط به همان دیتابیس بسازید.
2. `database/schema.sql` را با phpMyAdmin یا ابزار میزبان وارد کنید.
3. پروژه را خارج از مسیر عمومی آپلود کنید و Document root زیردامنه را روی `public/` بگذارید.
4. روی سرور `composer install --no-dev --classmap-authoritative` را اجرا کنید؛ اگر SSH/Composer ندارید، پوشه `vendor` تولیدشده در محیط هم‌نسخه PHP را نیز آپلود کنید.
5. `.env.example` را به `.env` تبدیل و مقادیر واقعی را تنظیم کنید:
   - `APP_ENV=production`
   - `APP_DEBUG=false`
   - `APP_URL=https://qr.example.com`
   - `SESSION_SECURE=true`
   - مشخصات اختصاصی دیتابیس
6. HTTPS را فعال و دسترسی مستقیم به `.env`، `app/`, `database/`, `tests/` و `vendor/` را از وب مسدود کنید. انتخاب Document root صحیح، این موارد را ذاتاً خارج از دسترس نگه می‌دارد.
7. به `/setup` بروید و نخستین مدیر را ایجاد کنید. پس از وجود مدیر، صفحه setup دیگر قابل استفاده نیست.
8. مجوز نوشتن PHP روی کل پروژه لازم نیست؛ فقط لاگ‌های وب‌سرور/هاست باید طبق سیاست میزبان قابل نوشتن باشند.

### ارتقا به QR Designer روی نصب موجود

برای نصب‌هایی که پیش از افزوده‌شدن Designer ساخته شده‌اند، فایل زیر را یک‌بار در دیتابیس فعلی Import کنید:

```text
database/migrations/002_qr_designer.sql
```

پوشه زیر نیز باید وجود داشته و برای کاربر PHP قابل نوشتن باشد؛ در DirectAdmin معمولاً سطح دسترسی `750` یا `755` کافی است:

```text
storage/logos
```

فقط تصاویر PNG، JPG و WebP حداکثر ۲ مگابایت پذیرفته می‌شوند. لوگوها بیرون از Document Root ذخیره می‌شوند. رکوردهای قدیمی بدون تغییر با قالب کلاسیک و امن باز می‌شوند.

### اگر Document root قابل تغییر نیست

پیشنهاد امن این است که محتوای `public/` در پوشه عمومی باشد و باقی پروژه یک سطح بالاتر قرار گیرد؛ سپس مسیر `vendor/autoload.php` در `index.php` متناسب با ساختار میزبان اصلاح شود. کل پروژه را بدون محدودیت دسترسی داخل `public_html` قرار ندهید.

## پشتیبان‌گیری و بازیابی

پشتیبان‌گیری:

```powershell
C:\laragon\bin\mysql\mysql-8.0.30-winx64\bin\mysqldump.exe -h 127.0.0.1 -u root --single-transaction --routines qr_manager > qr_manager_backup.sql
```

بازیابی در یک دیتابیس خالی:

```powershell
Get-Content -Raw qr_manager_backup.sql | C:\laragon\bin\mysql\mysql-8.0.30-winx64\bin\mysql.exe -h 127.0.0.1 -u root qr_manager
```

فایل `.env` را جداگانه و رمزگذاری‌شده نگه دارید. بازیابی را دوره‌ای در محیط آزمایشی امتحان کنید.

## چک‌لیست پیش از تولید

- دامنه و HTTPS نهایی شده و `APP_URL` دقیق است.
- `APP_DEBUG=false` و `SESSION_SECURE=true` هستند.
- کاربر دیتابیس اختصاصی و کم‌دسترسی با رمز قوی تنظیم شده است.
- Document root فقط `public/` است و directory listing خاموش است.
- نخستین مدیر با رمز منحصربه‌فرد ساخته شده است.
- QR پویای آزمایشی روی دامنه نهایی اسکن و ریدایرکت شده است.
- دانلود PNG و SVG، تغییر مقصد، غیرفعال‌سازی و بایگانی آزمایش شده‌اند.
- برنامه پشتیبان‌گیری دیتابیس و نگه‌داری لاگ میزبان مشخص است.
- PHP و وابستگی‌ها به‌روز نگه داشته می‌شوند.

## محدودیت‌های امنیتی و آماری

- آمار اسکن، «بازدیدکننده یکتا» نیست؛ اسکن تکراری، ربات و پیش‌نمایش لینک ممکن است ثبت شود.
- تشخیص دستگاه/مرورگر بر اساس User-Agent تقریبی است.
- IP خام ذخیره نمی‌شود و موقعیت جغرافیایی جمع‌آوری نمی‌شود.
- نسخه اول بازیابی رمز، ثبت‌نام عمومی، نقش‌های چندگانه و API عمومی ندارد.
- مقصد کد پویا fetch یا پیش‌نمایش سمت سرور نمی‌شود؛ بنابراین سطح SSRF ایجاد نشده است.
